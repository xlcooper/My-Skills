1. 先阅读本文件，确认项目边界和工作规则。
2. 阅读 `README.md`，了解项目的公开目标、安装和使用方式。
3. 阅读与任务直接相关的需求、设计、代码和配置文件：[列出实际路径]。
4. 任务依赖设备或工具链时，查阅本地 `PROJECT_ENVIRONMENT.md`。
5. 修改项目内容前后查阅并维护本地 `CHANGELOG.md`，避免重复记录或遗漏方向性变化。

日常工作不需要重新读取用于初始化项目的 Skill。

## 与用户协作

- 默认使用中文沟通。
- 先给结论，再简要说明证据、验证结果、阻塞项和下一步。
- 对范围清晰的请求直接推进；只有缺失选择会实质影响结果或超出授权时才询问。
- 明确区分已观察事实、用户决定、合理推断和未决假设。
- 采用满足需求的最小方案，避免冗余文档、过度设计和未经请求的扩展。
- 用户要求形成文件的结果必须写入项目文件，不能只留在对话中。
- 用户提出长期有效的新偏好或规则时，更新本文件的对应章节。

## 文档维护

- 每次完成一个有意义的项目内容修改后，在 `CHANGELOG.md` 增加带本地时间戳的摘要，并按长期方向动态整合旧记录。
- 只有设备约束、运行时、工具链、平台、Git 配置或项目要求发生实质变化时，才更新 `PROJECT_ENVIRONMENT.md`。
- 只有公开范围、安装、复现、使用、展示或导航发生变化时，才更新 `README.md`。
- `README.md` 永远面向外部读者，不包含本地环境摘要、内部变更摘要、执行报告或与用户沟通的内部规则。

## 完成标准

- 改动保持在请求范围内，并与现有设计一致。
- 相关验证已执行，或未验证项及原因已明确记录。
- `CHANGELOG.md` 已更新；环境或公开使用方式变化时，对应文档也已同步。
- 下一位人员或 Agent 能只依靠项目内文件继续工作。
